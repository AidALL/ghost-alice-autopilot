# Approved task continuation

Load this reference when the current-conversation model has identified necessary authorized follow-up work or must register an already authorized conditional dependency plan. The model makes that necessity and authority judgment; the Ghost-ALICE Autopilot API records the supplied plan. Admission checks the current selected criteria and boundary without requiring a completed response review or Stop application. Execution eligibility remains conditional on the recorded dependencies and applied criteria.

Core verification-before-completion owns claim/source and whole-answer review. Resolve its installed references/autopilot-publication.md when preparing a response with new claims. Use this reference for the Ghost-ALICE Autopilot plan handoff.

## Register the approved plan

An unmet criterion or successful publication is not an executable plan. The current-session assistant registers only executable steps already authorized by the human. Resolve `AUTOPILOT_SKILL_ROOT` from the trusted installed Ghost-ALICE Autopilot binding; its `adapters/autopilot_continuation.py` imports sibling modules, so add the `adapters` directory itself to Python's module path.

The assistant prepares a JSON object in permitted runtime scratch at absolute `PLAN_INPUT`. Its `expected_input_event_id` is the current canonical receipt/state event, not an old event attached to a new decision. Its `approval_evidence` is `{"decision":"approved","source":"<compressed actual human authorization and locator>"}`; `approve` and `go` are also accepted decision values, but the assistant cannot invent approval. Its `allowed_surfaces` is a nonempty string list of the actual approved boundaries. Each `items` element contains:

- `id`, `status`, `focus_layer` and `prompt`: a stable nonempty task ID, its actual current task state, the selected focus and the admitted task description. `prompt` remains plan history; continuation sends the currently needed information declared by the model. Do not admit an item as `completed` or `not_applicable`; use `blocked` for a missing required decision and `stopped` for an explicit stop.
- `allowed_surface`: nonempty strings within the approved `allowed_surfaces`; `depends_on`: known task IDs forming an acyclic dependency graph; `acceptance_criteria`: criterion descriptions. The latter two may be empty lists.
- `criterion_refs`: nonempty qualified references `{work_unit_id, contract_revision, criterion_id}` copied from the exact current selected, admitted, owned contract. No reference may occur twice within or across items. Omit `attempt` for its initial zero default; do not manufacture completion metadata.

The native host execution tool must retain the current trusted managed runtime environment, including its Core/runtime/owned roots, platform/project context, native v2 capability and any exact existing `GHOST_ALICE_AUTOPILOT_RUN_DIR` or `GHOST_ALICE_AUTOPILOT_CWD` overrides. CORE_ROOT is the trusted runtime GHOST_ALICE_CORE_ROOT (or supplied GHOST_ALICE_SKILLS_DIR fallback); LEDGER_ROOT, PLATFORM, SESSION_ID and the current event come from the exact hook receipt and canonical state. Those receipt bindings must match the runtime context. A missing compatible context leaves admission unavailable; creating a foreign run or inventing overrides is not recovery.

After binding those paths and receipt coordinates, use the exposed shell tool:

```bash
GHOST_ALICE_CORE_ROOT="$CORE_ROOT" \
GHOST_ALICE_SESSION_INTENT_ROOT="$LEDGER_ROOT" \
GHOST_ALICE_PLATFORM="$PLATFORM" \
GHOST_ALICE_SESSION_ID="$SESSION_ID" \
python3 - "$AUTOPILOT_SKILL_ROOT" "$PLAN_INPUT" <<'PY'
import json, os, sys
from pathlib import Path
sys.path.insert(0, str(Path(sys.argv[1]) / 'adapters'))
from autopilot_continuation import register_continuation_plan
plan = json.loads(Path(sys.argv[2]).read_text())
result = register_continuation_plan(dict(os.environ),
    expected_input_event_id=plan['expected_input_event_id'],
    items=plan['items'], approval_evidence=plan['approval_evidence'],
    allowed_surfaces=plan['allowed_surfaces'])
print(json.dumps(result))
PY
```

The API validates current selection, item references, surfaces and dependencies, persists the admitted queue in the resolved Ghost-ALICE Autopilot runtime target, and returns `{"status":"admitted","plan_id":"sha256:..."}`. The assistant retains that returned ID. An identical plan preserves its request history; an invalid binding or shape raises an error and admits no plan. Read the exit status/error rather than claiming admission from the proposed JSON. If scratch files are prohibited, the exposed Python tool may pass the same constructed object directly to this API; it does not waive any origin or schema requirement.

Plan admission freezes the current Core `boundary_ref`. A legacy plan without that binding holds continuation until explicit re-admission under still-valid human authorization; missing metadata does not create a new approval requirement.

Admission also freezes canonical absolute resource locations and descendant permission. Existing directories and explicit `/...` surfaces permit descendants; files and nonexistent exact paths remain exact even if later created as directories. An admitted `stopped` or `blocked` item cannot be released by editing scheduler state; reopening it requires a newly approved plan that resolves its stop or missing decision.

New admissions include `delivery_protocol: "autopilot-delivery-ledger.v1"` in the immutable definition. A prior plan without that protocol retains historical native receipt observation but cannot issue new execution-bearing requests or authorize actions. When still-valid human authority permits the remaining executable tasks, the current-session assistant constructs and registers that remaining plan using the current receipt and the Register the approved plan call above. It preserves original records and does not replay completed tasks or treat missing metadata as new user approval.

## Declare current needed information

The responding model supplies optional `continuation_feedback` in its existing Core response-route registration, with `schema_version: "continuation-feedback.v1"`, `control: "active" | "human-stop"` and an explicit `required_unprocessed` list. Each row contains nonoverlapping selected `criterion_refs`, the current necessity `reason`, minimum `next_information`, `prerequisite: "ready" | "missing"`, and `source_refs`. Original selectors are `{candidate_reference, source_id}` from existing Core candidates; the list may be empty. Core authenticates ownership and originals in the normal route transaction and resolves selectors to source-reference metadata without copying their bodies. Core's session-intent-analyzer ledger-schema reference owns the complete producer contract. No extra claim review or necessity model is called.

An undeclared necessity, an empty list, a human stop, a missing prerequisite or a changed boundary prevents dispatch. Empty feedback preserves unmet work. Ghost-ALICE Autopilot validates the entire current feedback-to-approved-task mapping, including rows held by Core's read-only `continuation_feedback_issues`, before selecting usable rows. Every row must map wholly and uniquely to one approved task, and distinct rows cannot map to the same task. An unsupported or ambiguous mapping holds dispatch as `continuation-feedback-unmapped`; source unavailability cannot make it eligible. For a valid mapping, Core issue entries hold only their referenced rows, and other approved groups can continue. Malformed issue metadata holds all dispatch. None of these outcomes erases independent proof bookkeeping or historical requests.

After privileged v2 application, `advance_continuation` maps accepted proof to completed tasks and compares current necessary rows with dependency-ready approved work. It records `continuation-request-queued` and a separate `delivery_requests` entry with `status: "pending"`, `host_receipt: "unknown"` and `execution: "unknown"`; queueing feedback leaves the task's execution state unchanged. The entry retains a semantic suppression fingerprint and `source_locator: {input_event_id, response_route_digest, pointer}` naming the existing immutable Core route declaration and exact necessity row. The digest excludes read-only current-input and source-issue metadata; no second declaration body is cached.

`autopilot_delivery.py` records the queued emission in the owned content-addressed store before the adapter emits feedback. Its immutable record binds the plan, task, request ID, fingerprint, original Core locator and canonical proof cycle. Only relevant canonical Core criterion invalidations create another work cycle; deleting mutable dispatch/action state does not. The module reconstructs `delivery_requests` and `request_history` from immutable emissions, native receipt observations and action attempts. These projections do not grant execution or authenticate a reported receipt. Superseded unknown emissions remain in `request_history`, keyed by request ID, so a later native record can acknowledge the original emission while the current replacement remains unknown.

Its payload contains `continuation: {status: "pending", request_emitted: true, task_id, criterion_refs, plan_id, host_receipt: "unknown", execution: "unknown"}` and a `systemMessage` containing current necessity, next needed information, original selectors/locations, approved surfaces and criterion references. The message also carries the stored `plan-id`, `request-fingerprint` and unique emission `request-id`. It does not resend the historical task prompt, complete answer, source body or ledger. At Stop, `_format_payload_for_hook` transports that new request in stdout JSON as `decision: "block"` with `reason` equal to `systemMessage`, including when an independent recording branch is parked. Returning this payload establishes neither receipt nor execution. If the host delivers it to the triggering conversation, its response model requests the authorized work tools. The Stop session identifies the intended destination; it does not establish reuse of a model process or create a delegated assistant. An approved plan can consume existing accepted proof during a non-closing partial or explanation response without creating a new publication obligation. Recording-only parked errors do not request this continuation block.

On a later Codex Stop, `advance_continuation` reads the transcript path supplied by the native hook once for all unknown requests. `observe_codex_receipts` requires matching native `session_meta` ownership and an `event_msg` / `item_completed` / `HookPrompt` record addressed to that session. Its text must contain the exact plan, task, request fingerprint and emission ID, with a valid original timezone-aware timestamp. A reopened/requeued task receives a new emission ID even when its semantic suppression fingerprint is unchanged; an earlier HookPrompt cannot acknowledge that new request. A match records `continuation-host-received`, stores the original event coordinate, digest and timestamp, and sets the request to `status: "received"`, `host_receipt: "observed"`. Repeated observation retains that first receipt and does not retransmit. Ordinary user text, tool echoes, compacted history, legacy feedback without request identity, foreign or malformed records do not establish receipt. This reader does not change task status or `execution: "unknown"`; task execution uses the separate native action wrapper below. Missing hook transcript paths leave receipt unknown without business replay.

On a later Claude Stop, the same caller selects `observe_claude_receipts` with the native hook transcript path and the authenticated session/plan/queued request identities. The reader accepts a main-session native user task notification with `promptSource: "system"`, `turnOrigin: "task_notification"` and `origin: {kind: "task-notification", producer: "session-task"}`, or a native attachment whose queued command has `commandMode: "task-notification"` and that same origin. It also accepts the observed native Stop attachment: `isSidechain: false`, `attachment.type: "hook_blocking_error"`, `hookName: "Stop"`, `hookEvent: "Stop"`, nonempty `toolUseID`, and nested `blockingError.blockingError` feedback. That attachment must have `renderedRole: "system"` and exactly one rendered content block wrapping the identical command and feedback in the native `Stop hook blocking error from command` system reminder. The original row must bind `sessionId`, nonempty UUID and timezone-aware timestamp to the intended session. The payload must carry exactly one complete `[autopilot]` approved-task declaration matching the plan, task, semantic fingerprint and emission ID. Human, SDK, peer, tool, meta-user `Stop hook feedback` text, generic `hook_success` or `hook_system_message` records, and unbound metadata echoes remain unknown. A positive match stores its original native coordinate, digest and time as delivery evidence only. A local parser check of a preserved native record does not establish that a later automatic Stop adopted the changed reader or that a task executed. Unknown receipt never prevents an independently authorized task action.

The current-session assistant receiving that feedback executes and verifies the requested action under host permissions and the selected skill instructions. Applied criterion proof can establish task completion independently of host receipt. Actual proof invalidation reopens only affected completed tasks and dependency checks, including a running descendant. A blocked branch does not cancel independent work. Historical `task-dispatched` events, task states and suppression fingerprints remain unchanged; their delivery and execution are reported as `unknown`, without inferring acknowledgment or resetting tasks to ready.

The same approved task, criteria, boundary, dependencies, surfaces and current semantic feedback emit a request once, then return `request_emitted: false` while retaining pending or unknown delivery. Source ordering, a candidate-wrapper change, timestamps or a new input ID alone do not reset suppression. The source identity includes its original ID, location, digest and available length/appendability. A latest human correction that changes the authenticated ready next information can replace a prior unknown request; the plan event preserves that previous unknown metadata. Absence of host acknowledgment alone does not cause retransmission. Keep `continuation` distinct from `completion_recording`.

The caller observes already emitted requests before selecting new execution. It authenticates the exact current runtime ledger/session/run against the immutable admitted `continuation-plan` and emission records. The native reader matches every unknown request ID, including superseded emissions for the same task. A match becomes an immutable `continuation-host-receipt` record; its reference supplies the projection's `receipt_ref`, original locator, digest and time. A stale, unselected or changed current route does not erase that historical observation. Reconstructing the delivery view preserves task status, immutable execution records, criteria and proof. Current route, frozen contract/boundary, necessity, source, stop and dependency checks still govern every new action or proof operation. A current human-stop prevents dispatch while allowing historical receipt observation; an OFF pause prevents both. Foreign targets, altered immutable records and incompatible plan bindings cannot adopt receipt evidence. Repeated observation retains the first receipt without replaying work.

## Execute and record an approved action

The current-session assistant uses `adapters/autopilot_execution.py` only inside the native tool call that performs a currently necessary approved action. The wrapper does not launch a model, supply tool permission or require observed receipt. It records the invoked callback, not an inference from unrelated tool activity. Ordinary work outside the wrapper remains unobserved by this connector. Native host Stop delivery and action execution remain separate paths.

The caller obtains `plan_id`, `task_id` and `request_id` from the actual queued feedback or its authoritative delivery request. The current intake receipt supplies `expected_input_event_id`; installed runtime bindings supply `source` and the adapter directory as in Register the approved plan. A prior request ID grants no authority. In the tool's Python operation, add that adapter directory to `sys.path`, import `execute_continuation_action` from `autopilot_execution`, and call:

```python
result = execute_continuation_action(source,
    expected_input_event_id=current_input_event_id,
    plan_id=queued_plan_id, task_id=queued_task_id, request_id=queued_request_id,
    action_id=current_action_id, operation=current_short_operation,
    resources=current_absolute_paths, action=perform_current_authorized_action)
```

This is a caller shape, not ambient permission or an executable example action. `action_id` is a stable ID for this particular action within this emission. `operation` is a short semantic description, never a raw prompt/command or tool output. `resources` lists the actual absolute file/directory paths the action uses within the task's approved surfaces; parent traversal and paths resolving outside those surfaces fail. An explicit `/...` surface also permits creation beneath a not-yet-existing directory. The callback performs only the action already permitted by the native host and user. Resource declarations are checked; this wrapper is not a sandbox or a command classifier.

Call the wrapper outside an existing Autopilot storage transaction. The wrapper commits its own started record before invoking the callback; caller rollback cannot erase that start and enable business replay. The callback closes any storage transaction it opens before returning; otherwise finish recording is unavailable while its actual result is preserved.

Before invoking the callback, the wrapper authenticates the exact current plan, owned route/input, frozen boundary/contracts, dependency-ready task, current necessity/prerequisite and immutable queued emission matching the supplied request ID, fingerprint and Core proof cycle. It checks existing immutable started/finished attempts for that action inside the same serialized transaction, then commits a new started record before invoking the callback and marks this task running. `host_receipt: unknown` does not prevent that action. When the callback returns or raises, it stores an immutable outcome with the original start/finish time and reconstructs `execution: observed`. The return value is forwarded as `result` without storage or content masking. An exception retains the original action failure; recording failure is separate. `status: recorded` means this action outcome was recorded, not that the business result or criterion passed. No criterion or task completion is inferred.

Reusing the same action ID after a recorded return yields `status: already-recorded`, `result: null` and its original evidence, without invoking the callback. It does not fabricate a second tool result. A changed operation/resource list, an active attempt or an already failed attempt cannot replay that action; inspect the original and apply the owned debugging/retry procedure before selecting a genuinely necessary new action. Recording failure after a returned callback yields `status: recording-unavailable` with the real result; preserve that result and repair only the required record without business replay. A replan/new emission during the action retains the original immutable outcome and cannot apply it to the newer request. Genuine human/cancellation evidence is separate from these automated local fixtures and task-bound action observations.

## Task context lookup

A queue message identifies its approved run and task. Optional task context is supplied as a task-record selector and field names. The current-session assistant uses the Approved queue API in SKILL.md to read that exact item and the fields needed before dependent work. The signal does not repeat decision lists, questions, constraints, non-goals or tool command bodies. The approved task retains its binding constraints. Allowed surfaces, criteria and current necessary next information remain explicit in the signal; receiving it grants no new authority.
